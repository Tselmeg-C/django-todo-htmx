# Groomed Issue Template

## Goal

One or two sentences describing what will be true when the issue is done.

## Acceptance criteria

- [ ] One observable, independently checkable result per line.
- [ ] Include relevant empty, invalid, failure, and edge cases.
- [ ] Keep implementation details out unless they are approved constraints.

## Out of scope

- Excluded work, linked to a follow-up issue when it remains part of the product plan.

## Constraints

- Relevant files and components.
- Required architecture and dependency decisions.
- Product, testing, accessibility, and compatibility guidance to follow.
